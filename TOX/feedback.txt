CODE REVIEW FEEDBACK
Files: TOX3GNN_experiment.ipynb, optim_TOX3GNN.py, tox21_analysis.ipynb


OVERALL
Good direction - Optuna + 30 seeds + scaffold split + significance test is the
right protocol skeleton, and the notebook is a clear improvement over the .py.
But the issues in section 1 would invalidate the headline numbers, so fix those
before spending more compute.


1. METHODOLOGY (fix first)
- Test set is used for model selection, so the reported AUC is optimistically
  biased. Notebook cell 20 trains on train+val merged, then uses the test
  loader for both best_auc and early stopping, and reports the max over 20 test
  evaluations. Keep val separate, select the epoch on VAL, evaluate test once.

- Early stopping never triggers: PATIENCE=30 but EVAL_EVERY=10 and
  MAX_EPOCHS=200 give only 20 evals, so every run does the full 200 epochs.

- round_to_4() is applied to the learning rate. lr is sampled log-uniform in
  [1e-5, 1e-3], so roughly a third of that space rounds to 0.0000 and the final
  model would train with lr=0. Round for display only.

- 30 seeds on ONE fixed split measures seed variance, not generalization. Use
  several scaffold splits x seeds with a paired test. Also give each baseline
  its own Optuna budget - tuned hybrid vs untuned baselines is the first thing
  a reviewer will attack.

- Scaffold split misses its target fractions (utils.py:305) - got 60/22/18, and
  4698/2427/706 in the analysis notebook. Sort groups by size descending and
  check len(idx)+len(group) <= cutoff.

- get_scaffold() (utils.py:262) returns "" both for acyclic molecules and for
  RDKit parse failures, so every ring-less molecule collapses into one group
  that lands entirely in one split. Separate the two cases.


2. BUGS IN optim_TOX3GNN.py
- The final training loop trains nothing. Line 320 rebinds the global optimizer
  to final_model.parameters(); the loop at line 367 backprops through `model`
  but steps `final_model` (grads are None). `model` stays at random init for all
  100 epochs, and those AUCs are written to results_tox21/*.txt - likely where
  the 0.54-0.62 values come from.

- random.shuffle(data_list) at line 67 breaks the scaffold split: indices are
  computed from X (original order) but applied to the shuffled list, so it
  silently becomes a random split. The notebook is fine.

- AUC is computed on thresholded 0/1 predictions (lines 189-203) - that's
  balanced accuracy, not AUC. The notebook's evaluate_auc is correct.

- Line 207 labels recall_score() as `specificity`. Recall is sensitivity;
  specificity is TN/(TN+FP).

- No MolFromSmiles-is-None filter, so it crashes on the 7 unparseable SMILES
  that survive dropna (5832 -> 5825).

- Line 171 hardcodes the batch size in reshape. Use .squeeze(-1), not bare
  .squeeze() - that also applies to evaluate_auc in the notebook.

If this file is superseded by the notebook, delete it rather than leave it.


3. STRUCTURE / REPRODUCIBILITY
- Everything runs at module scope, so importing the file runs the whole
  experiment (that's why notebook cell 27 crashed). Wrap in functions +
  if __name__ == "__main__", and move paths/hyperparams into a config.

- The GNN class is duplicated 3x and scaffold_split 3x, each with different
  semantics. Move both into utils.py / models.py and import them.

- Notebook outputs are inconsistent: cell 20 ran sage_gin_sage, cells 22/24
  report gcn_gin_gin (0.7839 +/- 0.0092). Stale kernel state - restart and run
  all before saving, and read results from all_runs_summary.csv rather than the
  in-memory all_run_aucs. Also delete cell 27 (dead paste of the old script).

- results_tox21/*.txt are append-mode with no run/date/config header, so
  versions are interleaved (sage_sage_sage.txt is ~9900 lines). Stick with
  all_runs_summary.csv and stamp each row with config + git SHA.

- pos_weight=6 is hardcoded in ~4 places; the actual ratio is 4890/942 = 5.19.
  Compute it from the training split.

- Worth a paragraph in the thesis: tanh after every conv is unusual (ReLU is
  standard, and GIN's MLP already ends in ReLU); GATConv defaults to heads=1 so
  "GAT" here isn't multi-head; edge_attr is computed but never used by any
  layer - either use GINEConv/NNConv or drop it and say so.
